## はじめに

Vercelが2026年8月3日に「Next.js 16.3」の正式リリースを発表しました。
長時間のローカル開発セッションにおけるRAM使用量を最大90パーセント削減...! などの改善がまとまって入っています。

https://nextjs.org/blog/next-16-3

Next.jsで開発をしていると、`next dev` を立ち上げっぱなしにしたまま一日作業を続けて、いつの間にかローカルマシンのメモリがカツカツになっている、という経験がある方もいるのではないでしょうか。
ルート数が多いプロジェクトほどこの傾向は顕著で、他のアプリを開くたびに動作が重くなります。私はこまめに開発サーバーを再起動する、という運用でしのいでいるのですが、同じような境遇の方には朗報です。

Next.js 16.0（2025年11月）以来最大級のアップデートとのことなので、本記事では公式ブログの内容をもとに主要な変更点を整理します。

## 対象者

* Next.jsで開発サーバーのメモリ消費やビルド時間に悩んでいる方
* コーディングエージェント（Claude CodeやCursorなど）とNext.jsプロジェクトを組み合わせて開発している方
* Next.js 16系にアップグレードするかどうか判断材料が欲しい方

## 概要 : Next.js 16.3

Next.js 16.3は、先月公開されたプレビュー版で試験提供されていた機能が正式に安定版へ組み込まれたリリースです。既存アプリがコード変更なしで恩恵を受けられる改善と、フラグを有効にすることで使える「Instant Navigations」という新しい開発体験の両方が含まれています。

アップグレード自体は次のコマンドだけで完了します。
16.x 系列からのマイナーアップデートは、基本的にマイグレーションコードなしでそのままアップグレードできます。

```bash
# Next.js 16.x をお使いの場合（16.0 〜 16.2）
npm install next@latest
```
::: message
**Next.js 15.x 以前をお使いの場合**
15.x 以前からのアップグレードはメジャーバージョンアップ（16.0 経由）を挟むため、一部破壊的変更の確認が必要です。
公式の codemod を活用して段階的に引き上げることをおすすめします。
:::


## 主な変更点

### 1. 開発時のメモリ使用量を最大90パーセント削減

もっとも分かりやすい改善が、`next dev` 実行時のメモリ消費量です。Turbopackにデフォルトで有効化された2つの機能、ディスクキャッシュ（16.1で先行導入済み）とメモリ退避（memory eviction）の組み合わせにより、長時間の開発セッションでのRAM使用量が最大90パーセント削減されるとしています。

公式ブログに掲載されているベンチマークでは、50ルートをコンパイルした後のメモリ使用量が次のように改善したと報告されています。

| プロジェクト | Before | After | 削減率 |
| --- | --- | --- | --- |
| vercel.com（ダッシュボード） | 21.5GB | 2GB | 約90% |
| nextjs.org | 4,600MB | 840MB | 約82% |

:::message
これらの機能はいずれもデフォルトで有効なので、`next@latest` にアップグレードするだけで恩恵を受けられます。特別な設定は不要です。
:::

### 2. ビルドと型チェックの高速化

開発時だけでなく、`next build` にも同じディスクキャッシュの仕組みが適用されるようになりました。差分のないビルド成果物をキャッシュから読み込めるため、CI上でのリピートビルドが案件によっては最大5.5倍高速化したと報告されています。

あわせて、先月リリースされたTypeScript 7（既存の10倍速いとされるネイティブ実装）を型チェックに使えるようになりました。`typescript@^7` を導入するだけで `next build` 時の型チェックを高速化できます。

さらに、App RouterのSSRレイヤーでWeb StreamsからNode.jsのネイティブストリームに置き換えられたことで、変換コストが減り、負荷時に処理できるリクエスト数が最大22パーセント増加したとのことです。

### 3. Instant Navigations - SPAのような画面遷移

Server Componentsはアプリを軽量にする一方で、画面遷移時の体感速度がSPAに劣るという課題がありました。Next.js 16.3では「Instant Navigations」と呼ばれる一連の機能がオプトインで導入されました。

* Instant Insights: 遅い画面遷移を自動的に検出して知らせる開発者ツール
* Partial Prefetching: リンクごとにプリフェッチする量を細かく制御できる仕組み
* Better ISR: ビルド時に事前生成しなかったURLでも、初回アクセス時に即座にローディング画面を返せるように改善されたIncremental Static Regeneration
* Navigation Inspector: 画面遷移中のローディング状態を視覚的に確認できる開発者ツール
* Playwrightテストヘルパー: リファクタリングで遷移が遅くなっていないかを検証する `instant()` ヘルパー

これらは `next.config.ts` で以下のフラグを有効にすると使えるようになります。

```ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
};

export default nextConfig;
```

:::message
公式ブログによると、Instant Navigationsで導入された挙動は将来のメジャーバージョンでデフォルトになる予定とのことです。今のうちから仕組みを理解しておくと、将来のアップグレード時に慌てずに済みそうです。
:::

### 4. AGENTS.md同梱によるAIコーディングエージェント対応

こちらの機能も注目です。
AIコーディングエージェント向けの改善です。`next dev` を実行すると、プロジェクトのNext.jsバージョンに対応した `AGENTS.md` のブロックが自動生成・維持されるようになりました。この `AGENTS.md` は、プロジェクトのローカルの `node_modules` 内に同梱されたドキュメントを直接指し示す仕組みで、Claude CodeのようなコーディングエージェントがプロジェクトのNext.jsバージョンに合った公式ドキュメントを、追加のセットアップなしで参照できるようになります。

:::message
この仕組みの導入にあわせて、これまで最新ドキュメントをエージェントに渡すためだけに提供されていた既存のSkillsは廃止される予定とのことです。
:::

### 5. その他の注目アップデート

上記以外にも、実務で役立ちそうな変更が複数含まれています。

| 機能 | 概要 |
| --- | --- |
| プリフェッチリクエストの削減 | 一定サイズ以下のプリフェッチをまとめて送ることで、リクエスト数を削減 |
| 静的アセットのキャッシュ改善 | 不変な静的アセットをデプロイをまたいで再利用可能に |
| カスタムエラーバウンダリ | `catchError` により、`notFound` や `redirect` を妨げず、Server Componentsの再取得もできるエラーバウンダリを定義可能 |
| glob importのビルトイン対応 | Turbopackで `import.meta.glob` を使い、複数ファイルをまとめて読み込み可能 |
| root params | `next/root-params` で `[lang]` のようなルートレベルのparamsをprops経由なしに取得可能 |

実験的機能としては、Rust実装のReact Compiler（Babel実装比で最大46パーセント高速）や、ネットワーク切断時にリクエストを保留して再接続後にリトライする `experimental.useOffline` も紹介されています。

メモリ削減やビルド高速化はデフォルトで有効になるため、アップグレードするだけで恩恵を受けられます。
一方でInstant Navigationsは前述のとおりオプトインの機能なので、既存アプリにキャッシュの挙動を意識した設計変更が必要になる可能性があります。

:::message
本番アプリに導入する場合は、公式のCache Components移行ガイドを参照しながら段階的に進めるのが安全です。
:::

## おわりに

開発サーバーのメモリ使用量に悩まされていた身としては、今回のアップデートはかなり刺さる内容でした。
まずはメモリ削減とビルド高速化だけでも早めに恩恵を受けたいので早速アップグレードしました。

Instant NavigationsやAGENTS.mdの同梱は既存の開発フローに影響する部分もあるため、まずは手元のプロジェクトで試しながら少しずつ理解を深めていこうと思います。

本記事が、Next.js 16.3へのアップグレードを検討する際の参考になれば幸いです。
