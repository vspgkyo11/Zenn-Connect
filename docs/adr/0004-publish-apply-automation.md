# 0004. 記事公開と記事申請フォーム送信を Playwright スクリプトで自動化し、フォーム送信は手元の Mac で行う

- **Status**: Accepted
- **Date**: 2026-10-01

## Context

記事を公開するたびに、`published: true` への変更・commit・push と、社内の記事申請 Google Form
（記事申請お申し込み）への入力を手作業で行っていた。フォームは入力項目が多く（申請種別・氏名・投稿日・タイトル・URL・カテゴリー等）、
「回答のコピーを自分宛に送信する」の付け忘れで送信完了の確認ができなくなるリスクもあった。

フォームは組織アカウントでのログインが必須（メールアドレス収集が「確認済み」）で、Google Forms API には回答を送信する手段がない。
また初回運用で次の制約が分かった。

- Claude Code on the web のクラウド環境は egress プロキシで docs.google.com / zenn.dev への接続が拒否される
- クラウド環境は無操作で破棄されるため、数時間の待機には向かない
- Google は自動操作ブラウザからのパスワードログインを弾きやすく、2段階認証もある
- 「記事カテゴリー」は単一選択（ラジオボタン）、送信ボタン付近に reCAPTCHA がある

## Decision

- `scripts/zenn-publish-apply.mjs`（Node + Playwright）で「公開（git）」と「フォーム送信」を1コマンドにまとめ、
  Claude Code スキル `.claude/skills/zenn-publish-apply/` から呼べるようにする。
- Google 認証は **永続ブラウザプロファイル**（`~/.zenn-publish/chrome-profile`）に手動ログインを1回保存する方式を基本とし、
  パスワードによる自動ログインは任意の補助手段に留める。インストール済み Google Chrome を優先して使う。
- フォーム送信は **手元の Mac で実行** する。クラウドの Claude は git 工程（予約公開の push）までを担う。
- 公開時刻の指定は、プロセス待機（`--at`）に加えて Zenn の予約公開（`published_at`、`--reserve`）を選べるようにし、
  PC を起動し続けられない場合は予約公開を使う。
- フォームの要素は見出し文言・`data-value`・`aria-label`/アクセシブルネームで特定し、クリック後は `aria-checked` の反映を待って検証する。
  見つからない場合は検出した選択肢を出力して止まる（誤った内容で送信しない）。
- 本番前に `--dry-run` で入力済みスクリーンショットを確認できるようにする。

## Consequences

- 公開〜申請が1コマンドになり、入力ミスと「回答のコピー」の付け忘れがなくなる。
- フォームの質問文・選択肢が変わるとスクリプトの修正が必要（エラーメッセージで検知できる）。
- 手元の Mac とログイン済みプロファイルが前提。プロファイルのログインが切れたら `login` をやり直す。
- reCAPTCHA が出た場合は完全自動にはならず、`--headed` で手動対応が必要。
- `.gitignore` を `.claude/*` + `!.claude/skills/` に変更し、スキルだけをリポジトリで共有する。
